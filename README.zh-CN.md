# 墨 Sumi

一个汉字书法编辑器。输入一个字符，编辑其笔顺路径，为每一笔指定笔锋应该如何运动，然后导出由模拟毛笔逐笔书写的循环 GIF。

你可以自由使用、Fork，也可以只提取其中需要的部分。整个项目都可以自由修改和重新用于其他用途。

在线版本：https://sumi-kanji-editor.grok.me/

## 为什么制作这个项目

这个项目的主要用途，是制作完全可定制的汉字书法动画 GIF——**由你决定路径、笔触标记和毛笔，而不是使用固定的笔顺动画**。

它也可以用于儿童教育材料、汉字教学软件以及其他教育内容。与单纯显示笔顺不同，Sumi试图表现汉字实际书写时的笔锋运动、压力变化、顿笔、折笔和收笔等特征。

1. 选择一个字符（或一个较短的词组）
2. 选择毛笔——Kaisho、Wet、Dry、Goat——并调整滑块
3. 编辑或绘制中线，并放置笔触类型标记，使运动符合永字八法
4. 在书写面板中点击 GIF

文件会导出为 `sumi-永.gif`（或你输入的字符）。网格、幽灵轮廓、速度以及你对路径所做的修改都会被记录到动画中。

**永**是模板字符。它的推荐标记位置依据真实笔顺中线和永字八法设置。如果需要一组干净的标记，可以载入永并点击 Suggest，然后将其作为其他汉字的参考。

## 路径编辑器

打开“Edit path”后，界面会显示笔顺中线（来自 `hanzi-writer-data`），墨迹则由跟随该路径运动的笔毛模拟器生成。

| 工具 | 功能 |
| --- | --- |
| Move | 拖动顶点。点击线段可以插入一个点 |
| Draw | 点击放置节点，双击放置最后一个节点。新绘制的笔画会按照绘制顺序上墨 |
| Delete | 点击顶点或标记即可删除 |
| Suggest | 根据几何形状推测并放置笔触类型标记（永有专用模板）。Reset 恢复原始中线和标记。Clear 清除所有路径，让你从空白页面开始绘制；幽灵轮廓和纸张仍保持原字符的画布范围，不会因为新画了一条较短的线而自动缩放 |

只有在拖动结束或完成一条绘制路径后，毛笔才会重新进行模拟。

## 类型标记 — 永字八法

笔画本身没有预设类型。类型由标记指定。第一个类型标记从笔画起点开始决定整条笔画的类型；如果之后出现另一个类型标记，则从该位置开始一直使用新的类型，直到下一个标记或笔画终点。压力只是作用于该包络的倍率，不会切换笔画类型。

默认笔身厚度为毛笔完全按压时笔毛厚度的50%。压力达到2倍时会达到保留的最大值。

| 标记 | 英文 | 包络 |
| --- | --- | --- |
| 側 | Dot | 约30% → 80%。这是点，而不是线 |
| 勒 | Horizontal | 始终保持50%。横 |
| 努 | Vertical | 50% → 45%，保持45%，再45% → 50%。起笔时包含着笔 |
| 趯 | Hook | 前40%保持50%，随后逐渐减至0。提钩 |
| 策 | Rise | 起点11% → 路径45%处达到50%，随后逐渐减小。没有着笔 |
| 掠 | Sweep left | 整条路径约67% → 0，`(1−t)^0.88`（区间开始处的压力约比普通情况高1/3） |
| 啄 | Short left | 100% → 0，`(1−t)^1.35`。起笔包含着笔，并以最大压力落笔 |
| 磔 | Splay right | 前75%从10% → 100%，随后沿路径逐渐减至0 |

“Suggest”功能会尝试为汉字放置类型标记。不过，目前只有**永**默认拥有正确的笔画类型标记。选择其他汉字后，可以为各条路径添加类型标记，以达到你希望的书写效果。如果仅靠类型标记无法达到理想效果，可以使用压力标记进行更细致的调整。一个压力标记可以作用于整条笔画，也可以连续放置多个压力标记；它们之间的变化会平滑过渡。

### 永的推荐布局

| 笔画 | 标记 |
| --- | --- |
| 1 | 側 |
| 2 | 勒（靠近起点）、努（节点4之后）、趯（节点8之后） |
| 3 | 策（靠近起点）、掠（节点6之后） |
| 4 | 啄 |
| 5 | 磔 |

如果策和掠相接，策的上升只持续到掠标记的位置；之后由掠接管剩余路径，而不是在标记处突然消失。

**着筆（pre-path）**是在努、勒和啄开始沿着向量方向运动之前进行的一段短暂“倾斜并稳定笔锋”的动作。可编辑路径不包含这段动作。

## 收笔与辅助标记

| 标记 | 功能 |
| --- | --- |
| 圧 Pressure | 类型的倍率。一个标记会作用于整条笔画；两个标记之间会进行平滑过渡（第一个值从起点开始保持，最后一个值在终点之前保持） |
| 折 Fold | 折笔——使用保留的最大压力，并对方形转角的外侧进行斜接，使转角保持锐利 |
| 止 Stop | 顿住收笔——保持 ≥92% 的压力，稍微越过终点后再折返，形成泪滴状的墨团 |
| 払 Lift | 撇/扫尾式收笔——从该标记开始，厚度在剩余路径的末端附近逐渐收束成一点。笔毛会聚拢，而不是像梳子一样简单地抬离纸面 |

类型标记之后的路径会显示为该类型对应的柔和颜色，因此连续使用多个类型时可以直观看到它们的分界。

## 毛笔

Size 滑块表示毛笔完全按压时的接触范围。压力会缩放这个范围，因此在收笔抬起时笔毛会逐渐聚拢，同时接触纸面的笔毛也会从中心开始逐渐变化。这与 Krita 的毛刷 Scale 和 Photoshop 的毛笔 splay 概念类似。

预设：

- **Kaisho**（狼毫）
- **Wet**
- **Dry**（飞白）
- **Goat**（柔软，在转弯时会有滞后）

Size、笔毛数量、splay、墨量、硬度（stiffness）和柔软度都可以实时调整。

Wet 的间隙填充只针对当前笔画进行，不会跨越不同笔画填充。因此，本来应该保留的笔画之间的空白仍然是纸张。

## 运行

```text
npm install
npm run dev
```

然后打开 Vite 输出的 URL（默认是 `http://localhost:8080`）。

```text
npm run build      # 生产环境构建
npm run typecheck
```

Node 22。技术栈为 TanStack Start、Vite、Tailwind v4。认证以及可选的收藏夹数据库使用 Postgres（生产环境使用 Neon，本地使用 PGLite）。如果需要保存收藏的汉字，可以使用 Google / X 登录。路径编辑保存在浏览器中。

## 再利用

MIT 许可证。你可以复制此仓库，将 `src/lib/brush/` 提取到其他项目中，更换纸张效果，删除 UI——无需获得许可。

如果你发布了 Fork，在自己的 README 中提及本项目是友好的做法，但不是必须的。如果仍然使用 `hanzi-writer-data` 提供的笔顺中线，请保留其归属声明。

## 项目结构

```text
src/lib/brush/     笔毛模拟、湿纸处理、路径标记、笔画准备、GIF 导出
src/lib/kanji/     汉字数据加载、预设
src/components/    工作室、纸张、路径编辑器和工具栏
src/routes/        页面和认证
```

如果你想把毛笔部分提取到自己的项目中，以下文件尤其值得关注：

- `src/lib/brush/bristles.ts` — 笔毛物理、压力缩放的展开、印章
- `src/lib/brush/wet.ts` — 按笔画进行的间隙填充（不会跨笔画）
- `src/lib/brush/engine.ts` — 着筆、止め钩、折れ斜接、磔的包络
- `src/lib/brush/edits.ts` — 标记、连续标记、永模板
- `src/lib/brush/gif-export.ts` — 使用同一播放器导出循环 GIF
