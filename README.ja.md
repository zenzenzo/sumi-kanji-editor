# 墨 Sumi

[English](README.md) · [简体中文](README.zh-CN.md)

漢字のパス、曲線、筆圧、筆法、書き順を編集し、毛筆シミュレーションによるループ GIF を作成する書道エディタです。教材、書き順の説明、イラストなどに利用できます。

**ライブ版：** [sumi-kanji-editor.grok.me](https://sumi-kanji-editor.grok.me/)

## ローカルで起動する

Node.js 22 と npm を使用します。

```sh
npm ci
npm run dev
```

http://localhost:8080/ を開きます。ポート 8080 が使用中の場合、起動は失敗します。

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

React、TypeScript、TanStack Start、Vite、Tailwind CSS v4、Nitro を使用しています。本番ビルドは Vercel 向けで、出力先は `.vercel/output` です。現在の `npm run preview` は、この出力形式の本番プレビューには対応していません。ローカルでの編集には開発サーバーを使用してください。

ローカルでは PGLite がデータベースの代わりになるため、データベースの設定やログインは不要です。Postgres を使う場合は `DATABASE_URL` を設定します。設定されていれば、ビルド時に SQL マイグレーションを実行します。公開版の Google/X ログインは Grok の認証連携を利用しており、別の環境で公開する場合は認証の設定も必要です。

## 編集と書き出し

文字または短い熟語を入力し、Kaisho、Wet、Dry、Goat から筆を選びます。**Edit** でパスやピンを編集し、**GIF** でアニメーションを書き出します。

GIF には現在の曲線、書き順、ピン、筆の設定、速度、グリッド、参照輪郭が反映されます。**Export paths** は編集内容を JSON としてダウンロードします。JSON の読み込み機能はありません。

編集内容はブラウザーのローカルストレージに保存されます。別のブラウザーとは同期されません。ログイン後に使用できる **Save** は、お気に入りの文字を保存する機能です。

| 操作 | 動作 |
| --- | --- |
| Move | ノードをドラッグして移動。ノード間をドラッグして曲線に変更。線分をクリックしてノードを追加。曲線の分割時も形状を保持します。 |
| 始点 | Move で最初のノードをクリックすると、開始角度と開始筆圧を編集できます。角度は紙面を基準とします。 |
| Earlier / Later | Move でノードを選択し、その筆画全体を書き順の前後に移動します。曲線とピンも一緒に移動します。 |
| Draw | クリックでノードを置き、ダブルクリックで終了。新しい筆画は書き順の末尾に追加されます。 |
| Delete | ノードまたはピンを削除します。 |
| Suggest | パスと開始設定を保持したまま、筆法のピンを推定し直します。 |
| Reset | 表示中の文字の編集を破棄し、組み込みの初期状態に戻します。 |
| Clear | パスを消し、白紙から描きます。 |

曲線は二次ベジェ曲線です。編集表示、筆のシミュレーション、GIF は同じ曲線を使用します。

## 基準となる 永

[`src/lib/brush/yong-template.ts`](src/lib/brush/yong-template.ts) に、作者が編集した 永 の正式なテンプレートを保存しています。ノード、曲線の制御点、ピン、書き順を保持しています。最新の点の筆圧 1.35 倍と、第三画の 1–1.3 倍の筆圧設定も含みます。

個人の保存済み編集がなければ、このテンプレートを読み込みます。**Reset** でテンプレートに戻り、**Suggest** では現在のパスを保持してテンプレートのピン配置に戻ります。

| 書き順 | 筆法 |
| --- | --- |
| 1 | 側 Dot |
| 2 | 勒 Horizontal → 努 Vertical → 趯 Hook |
| 3 | 策 Rise → 掠 Sweep left |
| 4 | 啄 Short left |
| 5 | 磔 Splay right |

## データベースのパス整理

元のデータには、筆の入りや収筆の形が中心線に含まれていることがあります。Sumi では、その形を筆法と筆圧で表現します。

- 長さが 90 以上で、全長の 60% を超える部分が軸から 12° 以内の直線的な横画・縦画は、本体の二つのノードに整理できます。横画の約 5° の上がりは保持します。
- 小さな始点・終点の装飾を除去しますが、鋭い折れ、上向きの鉤、大きな曲線は保持します。宀 の横画と鉤も保持します。
- 全体が Short left と判定された筆画では、短い入りの急な曲がりに限り、最初の一つか二つのノードを取り除きます。
- 永 はデータベースの整理ではなく正式なテンプレートを使用します。

これは推定処理です。他の文字の判定やピンは自由に修正できます。保存済みの編集は、限定的な旧データ修復を除き優先されます。

## 筆圧と筆法

最初の筆法ピンが始点からの筆法を決め、後続のピンで切り替わります。筆圧ピンは最終的な筆圧に倍率を掛けます。

- **Dot：** 本体筆圧の 0.75 倍から始まり、長さの 75% で 1.35 倍、終点で 1 倍。丸い終端になります。
- **Horizontal：** 均一な本体と自動の収筆。Stop は不要です。
- **Vertical：** 止める場合は Stop で丸い終端にし、鉤がある場合は折れたノードに Hook を置きます。
- **Hook：** 直前の 10% で筆圧が非線形に 1.5 倍まで増加し、その後は払いに向けて減少します。
- **Rise：** 横画と同じ入りと太さで始まり、最初の 20% の後から 0.25 倍まで細くなります。横画の収筆はなく、次の筆法に低い筆圧を引き継ぎません。
- **Sweep left / Short left：** 開始筆圧の倍率は標準で 1 倍。終端へ向かって細くなります。

開始の動作は、パスの最初の 20% に含まれる筆圧と向きの変化です。標準の角度は Vertical が **135°**、Horizontal と Rise が **110°**、その他が **160°**。開始筆圧の倍率はメニューから **0.25–3 倍** に変更できます。Horizontal、Vertical、Rise の標準値は **1.9 倍**です。

横画の収筆は開始の筆圧変化を逆にした形で、約 15% 強くなります。横画から別の筆法に移る際は、折れの前でこの収筆を行い、次の部分の最初の 20% で余分な筆圧を解放します。

筆圧ピンは入りと収筆にも反映されます。Fold は角の筆圧を強め、Lift は細い終端へ筆圧を下げます。詳細な数値は [英語版](README.md#stroke-types-and-pressure) を参照してください。

## 筆の描画と公開環境

毛束をばねと減衰でシミュレーションします。筆圧に応じた毛束の前方移動と低圧時の補正は連続的に変化し、点の途中で急に跳ねる現象を防ぎます。開始部分の最初の 8% では墨をつなぎ、粗い毛束の跡をなじませます。その後の質感は保持します。筆の向きと進行方向を分けて扱い、ねじれやパスの逸脱を防ぎます。GIF は全フレームをメモリーに保持せず、順次処理します。

Grok の PWA、プレビュー連携、認証補助、`startup.sh` は現在の公開環境で使用します。他の環境へ移行する際は、ビルドと認証の設定も変更する必要があります。

生成された `.vercel/output` とローカルの QA 画像は Git の対象外です。参考画像を二つ保持し、古いソースのコピー、未使用のマルチプレイヤーコード、汎用の Grok 作業ガイドを削除しました。`AGENTS.md` には本プロジェクトの作業指針を記載しています。
